# 墨舟

墨舟是面向中文长篇小说作者的 macOS 桌面编辑器。它把正文写作、章节管理、故事 Agent、人物关系和模型对话放在同一个本地优先的工作区中。

## 已实现能力

- 多作品管理：创建、切换作品；每部作品的章节、正文和故事分析彼此隔离。
- 章节管理：命名创建章节、切换章节、保存正文、更新章节字数和状态。
- 版本历史：每次保存保留最近 30 个章节版本，可恢复到编辑器后再确认保存。
- Markdown 导出：按章节顺序导出整部作品的已保存正文。
- 本地正文导入：支持 `.txt`、`.md`、`.doc` 与 `.docx`，导入后预览并选择替换当前章节或追加到末尾。
- 舒适写作：正文编辑区独立滚动，页面不跟随滚轮移动；首次进入章节时定位写作区域，输入过程不强制跳转。
- 正文排版：工具栏支持宋体、黑体、楷体与系统字体，15–20 px 字号和紧凑／正文／舒展三档行距；每部作品独立记住选择。
- 码字会话：在顶栏的保存／导入操作旁开始、暂停、继续或结束一次码字；实时记录本次净增字数、有效写作时长和字／分钟，结束后保留当前作品最近 60 次会话记录。
- Pi Agent Core：模型请求由 [Pi Agent Core](https://github.com/earendil-works/pi/tree/main/packages/agent) 驱动，支持 Agent 状态、工具调用与上下文裁剪，并兼容已配置的 OpenAI 兼容接口。
- AI 续写：使用已配置的 OpenAI 兼容接口续写正文；没有 API Key 时仅插入明确标识的演示内容。
- 故事 Agent：只根据已保存章节生成摘要、故事线、人物状态、关系与一致性提醒。可在保存时触发、手动触发，或按 5／15／30 分钟周期触发。
- 写作搭档：基于已保存章节和故事分析回答提问、推演冲突或检查人物动机。
- 创作工作组：写手、编辑与读者 Agent 围绕同一份已保存正文进行圆桌协作；按“写手提案 → 编辑审稿 → 读者反馈 → 写手修订”分阶段传递发言。作者可以暂停、打断当前发言、向任一 Agent 插话并在原阶段继续；所有插话会进入共享上下文。当前作品保留最近 12 轮记录，圆桌结论不会自动改写正文。
- 分层记忆：每次 Agent 请求按“作品总览与一致性提醒 → 人物和情节工作状态 → 相关章节与资料库摘录”构建有上限的上下文；不再把整部小说一次性塞进提示词。
- 写作 Skills：作品级内置 Skill 可单独启停，也可以安装自定义 JSON Skill。
- 公开网络搜索：资料库可直接检索公开网页的标题、链接与摘要并一键收藏；Pi Agent 也可按需调用相同的 `web_search` 工具补充书目、作者和评论参考。
- 模型配置：支持 Moonshot、DeepSeek、本地 Ollama 与其他 OpenAI 兼容 API；可测试 `/models` 连接。

## 快速开始

```bash
npm install
npm run tauri dev
```

开发时 Web 界面运行在 `http://127.0.0.1:1422`。构建 macOS 安装包：

```bash
npm run tauri build
```

## 配置模型

在右上角设置中填写：

1. 服务商和模型名称。
2. OpenAI 兼容接口根地址，例如 `https://api.moonshot.cn/v1`。
3. API Key。
4. 故事 Agent 的自动整理频率。

应用使用 Pi 的 OpenAI Completions 适配器请求续写、故事整理和写作搭档；连接测试使用 `GET /models`。请只使用你信任的模型服务商。

## Skills 与分层记忆

从顶栏的“Skills”打开当前作品的写作规则。内置 Skills 包含伏笔与一致性、人物动机和网文节奏；切换会立刻影响之后的 Agent 请求。自定义 Skill 可粘贴以下 JSON 安装，内容保存在当前作品本机数据中：

```json
{
  "name": "场景调度",
  "description": "让场景中的行动更清晰",
  "instructions": "建议时优先给出人物动作、空间变化和感官细节，不要替作者改写既有事实。"
}
```

分层记忆只会向模型提供：作品摘要和一致性提醒（长期层）、人物/情节状态（工作层），以及按照问题检索出的最多 3 个章节和 2 条资料库摘录（检索层）。正文仍只会在用户发起 AI 操作时发送给已配置服务商。

网络搜索仅处理公开搜索结果页中的标题、链接和摘要，不会抓取结果页、下载小说或导入受版权保护的小说全文。

## 数据与隐私

正式版以本机 SQLite 数据库作为主存储：macOS 默认位于应用支持目录下的 `inkstone.sqlite3`，章节以独立记录写入，不会因作品拥有数千章而在每次保存时重写整部作品。首次启动会自动复制既有 WebView 数据；迁移完成后，WebView 本地存储不再是主副本。

每次保存正文还会写入用户可见的镜像目录：`~/Documents/墨舟作品/<作品ID>/chapters/`。每章为一个 Markdown 文件，另在 `backups/` 中保留最近 20 份该章自动备份；可以直接复制整个作品目录做异机迁移或灾备。它不会自动把正文上传到服务器；只有点击续写、故事整理或发送写作搭档消息时，相关已保存文本才会发送给你配置的模型服务商。

模型 API Key 当前仍保存在本机作品库中；正式发布前还应迁移到 macOS Keychain。

## 项目结构

```text
src/
  components/   编辑器、模型设置、洞察、关系图与对话组件
  services/     模型请求、故事 Agent、本地存储
  types/        作品、章节、人物与故事线类型
  data/         演示数据
src-tauri/      Tauri macOS 容器与打包配置
```

更多实现细节见 [架构说明](docs/architecture.md)。
