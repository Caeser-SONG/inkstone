# AI 故事操作系统：需求拆分

## 1. 产品目标

墨舟不把 AI 定位为一次性续写工具，而是让它维护一份**可验证、可更正、可用于后续创作的故事状态**。作者始终拥有最终决定权；AI 不自动改写正文或把推断当作事实。

核心体验：作者保存一章后，能在一分钟内知道故事发生了什么变化、哪里可能冲突、下一章有哪些可选方向；需要时可召开写手、编辑、读者的创作会议。

## 2. 非目标

- 不做投稿平台、社区、任务积分或内容分发。
- 不下载、分析或复述受版权保护的第三方小说全文。
- 不在用户没有确认的情况下修改正文、角色设定或故事线。
- 第一阶段不承诺通用“模仿作者文风”或完全自动生成整部长篇。

## 3. 需求总览与优先级

| 编号 | 能力 | 优先级 | 依赖 |
|---|---|---:|---|
| R1 | 证据型故事记忆 | P0 | 已保存章节、模型配置 |
| R2 | 保存后的故事变化报告 | P0 | R1、章节版本 |
| R3 | 本章驾驶舱与一致性检查 | P0 | R1、R2 |
| R4 | 创作会议（写手/编辑/读者） | P1 | R1、R3、Pi Agent |
| R5 | 作者创作约束与长期偏好 | P1 | R1、Skills |
| R6 | 分叉剧情推演 | P2 | R1、R4、章节/故事线版本 |

## 4. R1：证据型故事记忆（P0）

### 用户故事

作为作者，我保存章节后，希望 AI 自动提取人物、地点、事件、设定、时间线和伏笔；我能核对其原文来源，并纠正 AI，避免错误记忆影响之后的建议。

### 功能需求

1. 每次故事整理仅以**已保存章节**为事实来源；未保存草稿不得进入长期故事记忆。
2. 每条记忆包括：类型、内容、状态、置信度、首次出现章节、最后更新章节、原文证据片段和创建/更新来源。
3. 记忆类型至少覆盖：人物状态、人物关系、地点/组织/物品设定、事件节点、时间线、伏笔。
4. 每条由 AI 新建或更新的记忆显示为“待确认”；作者可确认、编辑、合并、忽略或标记为过期。
5. 点击记忆卡可定位到对应章节与原文片段；无法提供证据的条目不得自动进入“已确认”。
6. 作者手动确认的设定优先级高于 AI 推断；后续 Agent 请求必须遵守。

### 验收标准

- 给定一章包含人物关系变化和新线索的已保存正文，故事库能生成至少一条带章节与原文片段的待确认记忆。
- 作者将条目改为“已确认”后，下一次 Agent 建议引用该结论而不与之矛盾。
- 删除/忽略条目后，后续故事记忆和 Agent 上下文不再采用该条目。

## 5. R2：故事变化报告（P0）

### 用户故事

作为作者，我不想每次保存都读一篇重复摘要；我只想知道这一章相对上一保存版本究竟改变了什么。

### 功能需求

1. 每次保存后比较“上一已保存版本”与“当前已保存版本”，生成变化集而非全文重述。
2. 变化按以下类别展示：新增事实、状态变化、推进/回收伏笔、潜在冲突、待确认推断。
3. 每项显示影响对象、简短原因和至少一个来源引用。
4. 作者可将某项标记为“这是有意改动”，系统将其记录为创作决策，避免反复报警。
5. 不配置模型时仍显示基础文本版本差异，但明确标示“未进行 AI 故事分析”。

### 验收标准

- 人物从“未知身份”变为“确认是卧底”时，报告能标为人物状态变化并引用新旧章节。
- AI 检出角色受伤后下一章行动不一致时，报告能列为潜在冲突；作者标为有意改动后不再重复提示。

## 6. R3：本章驾驶舱与一致性检查（P0）

### 用户故事

作为作者，开始新章前我希望快速看到必须延续的前情；写完后我希望知道本章是否违背角色动机、时间线或既定设定。

### 功能需求

1. 章节编辑页提供可收起的“本章驾驶舱”，默认不侵占正文宽度。
2. 驾驶舱显示：本章目标、前情摘要、在场人物当前状态、待回收伏笔、作者已确认的约束。
3. 支持作者填写或由 AI 建议本章目标、冲突和章末钩子；建议不会自动写入正文。
4. 保存后执行一致性检查，按“阻塞问题 / 注意事项 / 可选建议”分级，且必须有出处。
5. 作者可忽略、标记有意为之，或要求 Agent 给出修复方案；修复方案只能以建议形式出现。

### 验收标准

- 不打开驾驶舱时，编辑器正文区域与当前体验一致。
- 检出结论可以跳转至相关旧章或当前章句段。
- 无模型时，目标和前情仍可人工编辑、保存与展示。

## 7. R4：创作会议（P1）

### 用户故事

作为作者，我希望在一个议题下同时获得写手的剧情方案、编辑的逻辑审查和读者的读感反馈，并可随时改变讨论方向。

### 工作流

1. 作者输入议题与约束，例如“让主角发现真相，但暂不决裂”。
2. 写手提出 2–3 个有取舍的场景/剧情方案。
3. 编辑检查每个方案与已确认设定、人物动机、时间线和伏笔的冲突。
4. 读者评估情绪、爽点、信息量和章末钩子。
5. 作者选择方案、要求混合方案、插话或暂停。
6. 系统生成一份“创作决策”，由作者确认后进入项目记忆；不会改写正文。

### 功能需求

- 三类 Agent 共享同一份有界故事上下文与会议记录，但有不同职责提示词。
- 每轮显示发言状态、证据来源、消耗/模型信息和停止按钮。
- 作者可以随时打断、指定任一 Agent 回复、修改议题后继续。
- 会议决策可以转为本章目标、待办或临时剧情分支。

### 验收标准

- 用户打断后不再继续流式输出；继续会议时保留已确认的发言和作者插话。
- 会议结论不改变章节正文，只有作者点击应用时才写入本章目标或故事记忆。

## 8. R5：作者创作约束与长期偏好（P1）

### 功能需求

1. 作品级“创作宪章”可编辑：叙述视角、受众、章节节奏、题材禁区、角色底线、语言禁忌等。
2. 将“AI 建议 → 作者确认/否决”的反馈转成可查看的偏好候选，不能静默学习。
3. 作者可启用/停用每条约束，并知道它会影响哪些 Agent/操作。
4. 约束与 Skills 分开：约束是作品事实/偏好，Skill 是可复用的工作方式。

### 验收标准

- 已启用的“第一人称、不使用网络热梗”能出现在续写和会议的指令上下文中。
- 作者停用规则后，之后的请求不再传入该规则。

## 9. R6：分叉剧情推演（P2）

### 用户故事

作为作者，我希望比较两个剧情选择可能造成的后果，但不污染正式故事线。

### 功能需求

1. 从某一章节或会议决策创建临时分叉，填写假设条件与观察范围（例如后续 3 章/10 章）。
2. Agent 对每条分叉推演人物动机、伏笔回收、节奏风险和读者预期，并明确其为假设。
3. 并排比较分叉；作者可丢弃、归档、或将一条分叉转为“正式创作决策”。
4. 临时分叉不得自动修改已确认记忆、正文或正式故事线。

### 验收标准

- 两条分叉均有独立假设和结果，且从正式故事库中可区分。
- 丢弃分叉后，正式故事记忆和正文不发生变化。

## 10. 数据与隐私要求

- 故事记忆、确认状态、创作决策、会议记录和分叉均按作品隔离，存入本地 SQLite。
- 发送给模型的内容只限完成当前任务所需的已保存章节、已确认记忆和作者启用的约束；在界面中说明范围。
- API Key 移入系统钥匙串前，产品必须明确提示其现有本地保存方式。
- 所有 AI 产物记录模型、时间、任务类型和引用来源，便于审计和重跑。

## 11. 建议交付顺序

1. 统一故事记忆数据结构，并为现有摘要、人物、关系、故事线补来源字段。
2. 做记忆确认卡与保存后的变化报告。
3. 在编辑页接入可收起的本章驾驶舱和分级一致性检查。
4. 将现有多 Agent 圆桌重构为“议题 → 方案 → 审查 → 反馈 → 作者决策”的会议流。
5. 再实现创作宪章、剧情分叉和更丰富的章节看板。
