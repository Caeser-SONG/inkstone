# 产品待办

本文记录经实际体验竞品「作家助手」后的改进方向。目标不是复刻其投稿、社区与任务体系，而是让墨舟成为本地优先、由 AI 维护故事上下文的长篇小说工作台。

详细的用户故事、功能边界与验收标准见 [AI 故事操作系统需求拆分](ai-story-os-requirements.md)。

## P0：基础编辑体验

- [ ] 全文查找与替换；区分当前章和整部作品，并在替换前给出确认。
- [ ] 可恢复的编辑历史：展示保存版本、时间和字数差异，支持预览与恢复。
- [ ] 章节字数目标：设置每章目标，显示当前进度；与现有码字会话统计保持一致。
- [ ] 章节树支持卷（分卷）、拖拽排序、筛选、快速新建与折叠。

## P1：自动生长的故事资料库

- [ ] 将右侧洞察升级为可编辑、可确认的设定库：角色、地点、组织、物品、时间线与伏笔。
- [ ] 每条自动提取的资料都要标注来源章节和原文片段，作者可确认、修改、合并或忽略。
- [ ] 增加本章工作卡：本章目标、摘要、待解决冲突和伏笔状态；默认收起，避免压缩正文写作空间。
- [ ] 章节树/看板提供场景卡和时间线视图，用于观察章节节奏、角色出场和未回收伏笔。

## P2：可选增强

- [ ] 语音输入（明确使用系统听写或用户选择的本地/云端服务）。
- [ ] 起名与灵感工具，生成结果只作为建议，不写入正文或设定库。
- [ ] 双栏对照：正文与章节摘要、设定或历史版本并排阅读。
- [ ] 一键排版与发布导出：按目标平台规则输出，同时保留 Markdown 原稿。

## 产品边界与差异化

「作家助手」在章节树、传统编辑工具、字数目标、投稿与社区上较成熟。墨舟不以任务打卡、积分、投稿市场或社区运营作为近期重点；优先做以下差异化能力：

1. **本地优先与作者控制**：小说、资料和模型配置以本地 SQLite 与 Markdown 镜像保存，模型服务可由作者选择。
2. **可追溯的故事记忆**：AI 自动提取人物状态、故事线、时间线和伏笔，但每项都要能回到具体章节验证。
3. **多 Agent 协作**：写手、编辑和读者围绕已保存正文讨论，作者可以打断、提问和继续工作流，结论不会擅自改写原文。
4. **长篇连载驾驶舱**：为章节节奏、断章钩子、人物动机和前情一致性提供可操作的提示，而不是堆叠独立小工具。

## 竞品观察（2026-08）

从「作家助手」作品库与编辑页观察到：它提供新建卷/章、章节筛选、字体和背景、撤销、排版、插入、语音输入、全屏、查找替换、历史、取名、画师、发布入口；右侧将校对、拼字、大纲、角色、设定、灵感、双栏和妙笔做成独立面板，并在底部展示章节目标与本章字数。上述能力中，基础编辑和章节组织值得补齐；资料工具则应以“从正文自动提取、作者确认、可追溯来源”为墨舟的实现原则。
